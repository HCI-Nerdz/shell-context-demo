== Facsimile desks vs real windowing (advisory)

*What is fine in a marketing / explainer demo*

* Faux windows with title bars, close/minimize, drag, z-order focus, and simple resize on a **fixed desk canvas** inside the page.
* Showing layout *ideas*: decoupled index vs standalone, contained tiling zones, project-grouped manager beside a grid.

*What is painful (avoid pretending you shipped it)*

* True multi-monitor placement and drag across browser chrome.
* OS taskbar / HWND identity, real window piping, and anything that must leave the browser sandbox.
* Pixel-perfect “this is your desktop” claims — browsers will fight you.

*Recommendation*

Keep these Pages demos as **facsimile desks**. Real windowing stays in open-terminal / dew (native host). Do not grow the web mock into a fake OS WM.

== Demo controls (prompt desk)

* **Left-arrow** — cycle token focus (path → user → host → app tokens)
* **Right-arrow / Enter** — return toward input
* **PgUp / PgDn** — scroll paste preview (5 visible lines)
* **Theme** button — blue/grey default vs high-contrast
* **?** gutter — static prohelp placeholder (no backend)

== Typography

Prompt/cell mock uses the Open Shell curated monospace stack (system fonts only — no bundled faces):

[source,css]
----
font-family: "Consolas", "Cascadia Mono", "Courier New", monospace;
----

**Consolas** is the shipping default to fit OSO chrome visual language; users may override later in the real shell. Spec: link:https://opensh.org/docs/shell-architecture/typography.html[typography @ shell-architecture].
